## 公式資料を確認した主な補足

ページの該当説明付近と末尾にAWS公式資料へのリンクを置いた。原文の単純化や現在の仕様との違いを、以下のように扱った。

- Module 1：容量予測への依存は減るが、上限・起動時間・予算の確認は残る。複数AZへの配置だけでは自動復旧は完成しない。責任の境界はサービスごとに異なる。
- Module 3：サーバーレスでもサーバーは存在する。通常のLambda関数の上限15分を説明し、現在のManaged Instancesの一部の呼び出しまで一般化しない。ECS/EKSはコンテナ管理、EC2/Fargateは実行基盤として分けた。
- Module 4：データ配置の要件を国ごとに一律の法律として断定しない。Route 53の名前解決とCloudFrontの配信を分け、IaCによる構築とデータ複製・復旧を区別した。
- Module 5：デモで混在するリージョン/AZ表記を、同じリージョンのAZ A・Bへ統一。公開への到達にはIGW・経路・公開IPv4・通信許可が必要。プライベートサブネットからの外向き通信もあり得る。SGの初期ルールの例外、ACLの復路評価を補足。拠点間VPNと端末のClient VPN、Direct Connectと暗号化、地理的DNSとレイテンシーDNSを分けた。
- Module 6：EBSは終了時の削除設定に依存する。増分スナップショットも各時点の全体を復元できる。S3のオブジェクト上限は公式のマルチパート仕様に合わせ48.8 TiBと記載。Intelligent-Tieringは自動3層＋任意2層。耐久性と可用性、メタデータとタグ、保存料と取得料、バージョニングと権限を区別。Storage Gatewayは「教材で扱う3方式」とし、全方式が3つとは断定しない。S3のHTTPウェブサイトとCloudFront＋通常のS3オリジン＋OACも分けた。
- Module 7：通常のAuroraクラスターとAurora DSQLを別サービスとして扱った。DynamoDBにPartiQLやトランザクションもあるため「SQLは一切使えない」「関係やトランザクションが持てない」としない。キャッシュアサイドはアプリ側の処理であり、DBから直接キャッシュへ流れる図にしない。複製と過去時点からの復旧を分けた。
