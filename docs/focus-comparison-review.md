# 1テーマ・3つの見せ方の比較

2026年10月6日。ユーザーが承認した方針に沿い、Module 2のCloudWatch / Auto Scaling / ELBを扱う3つの短いサンプルを実装した。Module 2全体の新しい全文案、Module 3以降のページは作成していない。旧試作は保持し、Cは不採用の記録として残した。

入口：[`../prototypes/focus/index.html`](../prototypes/focus/index.html)。教材ホームと旧試作の記録からも開ける。

## 何を変えたか

| ページ | 主役と読む動作 | 実装 |
| --- | --- | --- |
| `annotated.html` | 1枚の構成図の経路をたどり、番号が対応する横の説明を読む | デスクトップは新しいSVG。リクエストは青、観測は紫の破線、台数制御は緑。狭い画面は同じ意味をHTMLの縦配置で保持 |
| `evolution.html` | 1台 → 台数だけ追加 → 入口と制御を追加、の構成自体を見比べる | HTML/CSSで3つの構成を描く。広い画面は横並びで図と注釈を整列、中間幅は各構成の図と説明を横に配置、狭い画面は縦に読む |
| `questions.html` | 問いと図で考えてから、答えと理由を開く | 3つの問いと小さなHTML図。標準の`details`を使い、キーボードでも開閉可能。選択・採点・履歴保存は追加していない |

色と文字サイズだけを変えた案にはしなかった。旧案の章レイアウト・サイド目次・図をそのままコピーせず、同じテーマに合う3つの読む動作を作った。どの案でも観測・台数の制御・リクエストの分散を区別し、上下限・起動時間・ELBとの連携条件を扱う。

注釈図では、ALBからのリクエストとCloudWatch / Auto Scalingの制御を別の経路へ配置した。構成変化の最後の図が長くなったため、台数制御の経路を3つの比較の下へ移し、比較図の高さと注釈の位置を揃えた。問いの案は回答と末尾補足の重複を減らした。

## 内容の確認

Module 2の元データと既存本文をもとに再編集し、AWS公式のターゲット追跡、Auto ScalingとELBの連携を2026年10月6日に確認した。資料リンクは各ページ末尾に置いた。設定値は学習用の例で、起動・ウォームアップの時間や、ELBのヘルスチェックとの役割の違いを補足している。

## 表示・操作の検証

- 比較ページと3案を320 / 390 / 600 / 820 / 1093 / 1280px幅で確認した（24条件）。問いのページは3つの回答を開いた状態も含めて検査。
- ページ全体と文字の描画範囲の横はみ出し、英単語の途中分割を調べた。見出しは意味のまとまりを編集し、短い役割名を途中で切らない。本文の末尾に「ます。」などだけが残る行も調べ、短い述語をまとまりとして補正した。`text-wrap: pretty`だけでは日本語の意味の切れ目を保証できなかったため、著者が短い句を選んで保持している。
- 図・説明・操作の配置を目視確認。図注釈の矢印とラベルの重なり、構成比較の高さの差、小さなプレビュー図の幅を修正。
- 図注釈のSVG内の文字がviewBox内に収まること、900px以下ではHTML版に切り替わることを確認。本文16px、役割14px以上を基本とし、図の文字を極端に縮めない。
- ローカルリンク、アンカー、重複ID、ARIA参照、HTMLタグの対応を検査。回答の開閉・案の切り替えを実ブラウザーで確認。

共通スタイルは`assets/css/focus.css`に分離し、サービスカテゴリの色は既存の`style.css`を参照する。追加JS・ライブラリ・外部画像は使っていない。採用後に価値のある部品だけを共通化する。

## 次の判断

「3つの役割を説明できる」「必要な説明へ戻れる」「図・文章・操作の量が適切」の3点で読み比べる。図注釈を基本に、構成の変化や問いを必要な箇所へ組み合わせることもできる。実装上の表示確認は、学習効果の優劣を示す評価とは区別する。選定後にModule 2全体へ展開する。
