## 比較する候補

入口は[`../prototypes/index.html`](../prototypes/index.html)。教材ホームからも開ける。

| 候補 | 読む流れ | 比較したい点 |
| --- | --- | --- |
| 既存案 | 概念 → 説明・図 → 補足 | 正確な説明を順に確認する読みやすさ |
| 案A：状況から学ぶ | 販売サイトの困りごと → 技術・図表 → 要点 | サービスを使う理由が先に分かるか、具体例が興味を支えるか |
| 案B：図から理解する | 全体の役割 → 図 → 役割カード → 補足 | 図を見るだけで関係を思い出せるか、復習時に探しやすいか |
| 案C：例えでつかむ | 2か所の作品の例え → AWSへの橋渡し → 技術・図表 | 既知の作品が理解のきっかけになるか、例えの量は適切か |

案Aは公開・性能選択・操作・負荷集中・障害・配送待ち・料金見直しの順。案Bは最初に役割を俯瞰し、各テーマで図を先に読む。案Cはフリーレンとシュタルクの役割をインスタンスの用途選択へ、遊真個人の成長とヒュース加入による戦力追加をScale Up / Outの違いへつなげる。作品設定は公式情報で確認し、対応の限界も記載した。作品を使わない章には通常の技術説明を置いた。

## 全体の範囲

3案ともEC2、仮想化、ハイパーバイザー、マルチテナント、インスタンスのカテゴリ・ファミリー・サイズ、操作方法とAPI、スケーリング、CloudWatch、Auto Scaling、高可用性、Region / AZ / Subnet、ELB、疎結合、SQS / SNS、料金の選択、重要ポイント、復習、公式資料を含む。

各案は7図・4比較表・4復習問題を持つ。案Bには追加の役割一覧を置いた。図は共通の概念図を使い、正確さと図の読み方を揃えた。文体・章順・図の前後の説明・要点の配置を変えている。

## 表示と操作の確認

Codexのブラウザーで比較ページと3案を、320 / 390 / 820 / 1093 / 1280px幅、高さ900pxで確認した（4ページ×5幅）。全20条件でページ全体の横はみ出しなし。図・表・モバイル目次の内部スクロールは意図した仕様。

- デスクトップの状況カード、役割一覧、SQS / SNS比較、作品の例え、複数AZ図を目視確認。
- モバイルでは比較図・役割カードが縦積みになることを確認。図のサービス名・役割の文字を縮小しない。
- SVGは表示幅820px以上を保持。狭い画面では横スクロール案内を表示し、キーボードの右矢印でもスクロールできることを確認。
- タイトルの意味のまとまりを`.phrase`で保持し、320pxでは27pxに調整。図の見出しに均等な折り返しを適用し、末尾の「る。」だけが次行へ落ちる状態を解消。
- 4案の切り替え、目次リンク、復習問題の開閉を確認。新ページでブラウザーの警告・エラーログなし。
- 全HTMLのタグ対応、見出しh1が1つ、重複ID、ARIA参照、ローカルリンクとアンカーを検査し、問題なし。共通JSの構文確認も通過。
- 主要テーマの欠落がないことを本文で確認。技術上の補足はAWS公式資料、作品設定はアニメの公式資料を参照。

確認画像：`variant-a-desktop.jpg`、`variant-b-desktop.jpg`、`variant-c-desktop.jpg`、`variant-b-mobile.jpg`、`variant-c-mobile.jpg`、`variants-overview.jpg`。

HTML/CSSは包含・比較・単純フロー、SVGは制御ループ・AZの分岐に使用。Mermaidは追加していない。外部ライブラリや画像がなくても本文と図表を表示できる。

## 次に決めること

表示確認は完了したが、学習効果の優劣はまだ検証していない。実際に読み、「続きを読みたくなる」「役割を説明できる」「後から探せる」の3点で比較する。1案を選ぶほか、案Aの具体例・案Bの図の順序・案Cの短い例えを組み合わせられる。

改善候補は、長い全文での読み疲れ、料金表の密度、作品の例えが役立つ範囲、モバイルSVGの横スクロールの使いやすさ。複数ブラウザーでの表示確認と実際の学習者による評価は未実施。採用する要素を決めてから共通CSSと指針へ反映し、Module 3以降へ進む。
