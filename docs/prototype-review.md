# Module 2 プロトタイプの検証記録

検証日：2026年10月4日。対象：ホームとModule 2。既存のトランスクリプトは変更していない。

## 完成した構成

学習目標 → EC2と仮想化 → 性能・料金の選択 → APIと操作方法 → スケーリングと監視 → 複数AZ・ELB → SQS・SNS → 重要ポイント・4つの復習問題 → 公式資料。

意味のまとまりに再編集し、コーヒーショップの演出は省略した。本文の図は7点（HTML/CSS 5点、SVG 2点）、比較表は4点。Mermaid・画像・外部CDNへの依存はない。

## 表示確認からの修正

- モバイルで目次内のHomeリンクが残るCSSの優先順位を整理した。
- 単純フロー内のインラインstyleを共通クラスへ移した。
- SVGの最小幅を820pxにし、補助文字が縮みすぎないようにした。
- 横スクロールの存在を文字で案内した。
- AZの包含図で、ラベルと矢印が交差しない経路へ修正した。
- HTML/CSSを整形し、共通部品を用途別にコメントで整理した。

## 元データの単純化への補足

| 元データの説明 | 教材での扱い |
| --- | --- |
| 停止・終了したインスタンスには料金が発生しない | インスタンス料金と、保持するEBS・利用コミットを区別 |
| 稼働中の1台へCPU・メモリを追加できる | 通常のEBS-backedインスタンスは停止・タイプ変更・再起動 |
| Savings Plansはすべて同じ範囲に適用 | Compute Savings PlansとEC2 Instance Savings Plansを区別 |
| Spotは終了2分前に通知される | 通常2分前、ベストエフォート、休止の例外を短く補足 |
| Auto Scalingで不要なインスタンスを停止 | 一般的なScale Inは終了と説明 |
| ELBの自動スケーリングは追加料金なし | 稼働時間・容量などに応じた従量課金と説明 |
| ELBは常に最も空いているサーバーへ送る | アルゴリズム依存、ALBの既定はラウンドロビン |
| キューは処理まで無期限に保管し、重複しない | 保持期限、可視性タイムアウト、成功後の削除、Standardの重複を補足 |
| SNSはその瞬間に聞かなければ通知が消える | 配信先に応じた再試行と、SNS→SQSの組み合わせを説明 |
| 直接通信はすべて密結合 | 依存の度合いが重要。ELBで配置依存を減らしても同期の依存は残る |

出典は本文の該当箇所にリンク。補足を一覧にしても、本文で全注意点を何度も繰り返さない。

## 再利用すると判断したもの

意味を持つ5カテゴリの色、Typography、サービス名＋役割、解説・補足・重要カード、図とキャプション、比較表、方向付きフロー、包含・収束・分岐・ループの使い分け、目次とモジュール間ナビゲーション。

Module 2の章順とSVG座標は共通仕様にしない。すべてのModuleで7章・7図・4表を要求しない。詳細は[design-guidelines.md](design-guidelines.md)。

## 改善余地と次の学習評価

表示と構造の妥当性は確認したが、「最も学習しやすい」構成が実証されたわけではない。

- 初学者にCloudWatch / Auto Scaling / ELBの役割を図だけで説明してもらう。
- SQS / SNSの違いを、配送と分析の具体例へ当てはめてもらう。
- 特定の説明を探す復習タスクで、目次の見つけやすさと移動の速さを確認する。
- スマートフォンで横スクロールに気付くか、図の全体像を保持できるかを確認する。
- 料金の比較表の情報量と、長い1ページでの読み疲れを評価する。
- 別ブラウザー、実機、スクリーンリーダー、印刷時の図表の分割を確認する。

結果に応じて指針を更新し、Module 3以降には更新した思想と部品を再利用する。
